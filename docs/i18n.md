# Web console translations

The web console uses next-intl. English is the source locale and every other locale is a JSON catalog under
packages/web/messages. Missing messages fall back to English at runtime, while CI applies stricter rules based on
the locale status.

## Add a language

1. Copy packages/web/messages/en.json to packages/web/messages/<tag>.json.
2. Add one entry to LOCALES in packages/web/src/i18n/config.ts. Use the language's native name for label, set
   htmlLang, text direction, the matching cronstrue locale, and start with status: draft.
3. Remove untranslated values from the new file and run
   node scripts/i18n-draft.mjs <tag> to print the missing keys and English source text.
4. Translate the draft. Preserve ICU placeholders and tags exactly. Apply a flat or nested JSON draft with
   node scripts/i18n-draft.mjs <tag> --apply draft.json; pass - to read stdin.
5. Run pnpm --filter @agentconnect.md/web i18n:check.
6. Ask a native speaker to review the catalog, then change its status to reviewed.

Adding a locale must not require changes outside the catalog and the LOCALES registry. Add aliases only when
browser language tags should resolve to the new locale. Do not map one writing system to another; for example,
Traditional Chinese must not silently select Simplified Chinese.

## Fix a translation

Find the semantic key in packages/web/messages/en.json, update the same key in the target catalog, and run
pnpm --filter @agentconnect.md/web i18n:check. Keep both files in the same key order.

Use keys shaped as Namespace.section.name. Use ICU plurals instead of string concatenation:

    {
      "count": "{count, plural, one {# organization} other {# organizations}}"
    }

For overflow testing, generate an accented English catalog that is about 30% longer:

    node scripts/check-i18n.mjs --pseudo /tmp/agentconnect-en-XA.json

## Locale status

| Status   | Meaning                                     | Missing keys                     |
| -------- | ------------------------------------------- | -------------------------------- |
| source   | The English source of truth                 | Fail CI                          |
| reviewed | Native-speaker-reviewed and ready for users | Fail CI                          |
| draft    | Work in progress                            | Warn in CI and show a Beta label |

Syntax errors, extra keys, placeholder mismatches, rich-text tag mismatches, and missing CLDR plural
branches always fail. A tag name is part of the contract, not decoration: `t.rich` resolves it by
name at runtime, so a translation that renames `<name>` or `<link>` fails the check.

## Style

Simplified Chinese uses full-width punctuation. Do not insert manual spaces between Chinese and Latin text. Keep the
product concepts listed as English in the glossary unchanged. New languages should add a short style section covering
tone, regional choices, punctuation, and terminology.

## Intentionally untranslated

- Agent output, IM messages, and webchat transcripts
- CLI, daemon, and setup-server terminal output
- Repository documentation and README files
- Developer-facing Zod issue text assembled in packages/web/src/lib/api.ts
- Generic HTTP status phrases that are only used by the network layer or logs

Right-to-left layout is not part of the first release. The locale registry already carries dir; an RTL locale also
needs mirrored icons and a layout audit before it can be marked reviewed.
