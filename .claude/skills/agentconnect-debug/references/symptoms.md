# Symptoms → first check

Each row records a prior mechanism and the first check that separated it from lookalikes. Treat it as a hypothesis for a new incident, not a conclusion; the linked [recipes](evidence-sources.md#9-diagnostic-recipes) say what each observation still cannot establish.

| Symptom                                                                                               | First check                                                                                                                                            | What it usually means                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A row or a directory the current code cannot have produced                                            | `daemon.agentVersion` of the daemon that wrote it                                                                                                      | An older release wrote it. Read the code at that tag; verify `main` on a pool agent.                                                                                                                                                                                                                                                                                                                                    |
| The review is posted on the PR, the Check still says analyzing                                        | `hook_review_projection` by `checkRunId`: `desiredState`, `observedState`, `attempts`, `lastErrorCode`, `writePhase`                                   | `attempts = 0` and desired ≠ observed: the write-back queue was starved by settled rows (fixed, PR #1350); it drains on its own. `attempts` rising with `ambiguous_write` and `writePhase = update`: the PATCH was lost during a Control Plane rollout; re-issued after ten minutes since PR #1897, on older Control Planes push an empty commit. desired = observed = `in_progress` with `attempts = 0`: see next row. |
| The Check is `in_progress`, `hook_run.status = running`, but the daemon store has no such `sessionId` | `sessions` on the dispatch daemon by `sessionId`; the daemon's root at the time                                                                        | The turn ran in a store that no longer exists (daemon restarted on another root, root deleted). The reaper marks it orphaned after `CRON_RUN_TTL_SEC`; a top-level comment mentioning the agent opens a new generation on the same Check.                                                                                                                                                                               |
| The Check stays `queued` while the turn is visibly running                                            | `hook_run.turnStartedAt` (null) against the store's session state (`prompting`)                                                                        | The daemon's `hook/start` barrier failed during a Control Plane reconnect, so the turn ran without review authority and the review call was refused; the Check lands neutral. Re-request the review. The retry budget being shorter than a reconnect is an open product gap.                                                                                                                                            |
| `hook_run.reason = daemon_offline` while the daemon shows `ready`                                     | Relay pod start times against `hook_run.startedAt`                                                                                                     | The relay had just restarted and had no daemon connection yet. The redelivery reconciler asks the code host to redeliver; see `redeliveryNextAttemptAt`.                                                                                                                                                                                                                                                                |
| A commit status, MR note, or Check details link says "Session unavailable", the final link works      | Whether that frame carried `acpSessionId` instead of the outward `sessionId`                                                                           | A frame minted from the ACP id. Every place the daemon sends a session id to the Control Plane must translate (`emitHookCompletion`, `hook/start` for each code host; PR #2166 fixed one that was missed). Not a visibility problem: hook sessions are org-visible.                                                                                                                                                     |
| Webchat shows "Could not reach the agent"                                                             | Gateway access log: the token mint paired with the `101` on `/webchat`                                                                                 | Mint without dial: the socket died in the browser or at the edge; stop reading server logs. Dial refused: the relay logs status and reason (since PR #2003).                                                                                                                                                                                                                                                            |
| A failed shell tool row with empty output and only an exit code                                       | The runtime's own log under the session or agent HOME                                                                                                  | The runtime saw the stderr, the transcript did not. Typical finds: a read-only filesystem, a git credential denial, a guardian rejection.                                                                                                                                                                                                                                                                               |
| The console shows a session on daemon A but the work happened on machine B                            | `session_meta.executorDaemonId`, `stayedHomeReason`; on B, `<root>/sessions/<leaf>/` or `hs/<12hex>/`                                                  | Cross-daemon execution. `memory_daemon_homed` and `shared_session` pin a session home; `holder_least_loaded` means placement ran and chose home. B never holds the agent's own directory.                                                                                                                                                                                                                               |
| A turn stopped after roughly 90 s with a stop nobody sent                                             | The daemon log around the stop, and whether the daemon was busy or restarting                                                                          | The session's lease was not renewed (heartbeat every 24 s); the fence stopped the turn. Look for what blocked the daemon's loop.                                                                                                                                                                                                                                                                                        |
| The daemon has said "restarting" for a long time after an upgrade                                     | `ps -o pid,ppid,lstart,comm`: two daemon processes                                                                                                     | The old process is draining a turn that never ends (a busy VM, a git command with no deadline). A drain deadline landed in PR #2302; the causes are tracked separately.                                                                                                                                                                                                                                                 |
| Many unrelated things fail at once; "skipped" everywhere; sessions will not start                     | `df -h` on the host                                                                                                                                    | Disk full. Do not run a whole-disk `du`; find the tree with a depth-limited one and let the operator delete.                                                                                                                                                                                                                                                                                                            |
| Shell commands in a workspace fail with E2BIG or "argument list too long"                             | `ls <agentsDir>/<agentId>/worktrees \| wc -l`                                                                                                          | Worktree pile-up; a few hundred entries exhaust `exec`.                                                                                                                                                                                                                                                                                                                                                                 |
| A follow-up sent through an external integration was silently dropped                                 | The `inbox` row's `integrationId`                                                                                                                      | The request arrived without an integration id and had nowhere to reply (issue #1734).                                                                                                                                                                                                                                                                                                                                   |
| Codex returns 401 with a service-account key                                                          | `codex exec` on the host with the same configuration                                                                                                   | Account-side. If the host CLI gets the same 401, nothing in the daemon path is at fault.                                                                                                                                                                                                                                                                                                                                |
| A skill or feature is reported "not installed" although the console shows it                          | Where the product must appear: repository-tracked skills in the clone, git-sourced skills at the agent level, managed bundles in `agent.managedSkills` | An empty `managedSkills` says nothing about git sources; an installation log at the wrong level says nothing about the install.                                                                                                                                                                                                                                                                                         |
| The daemon is up, the Control Plane sees it, but sessions or directories are missing                  | `agentconnect status` root against `config.json` and the store on that root                                                                            | The daemon started on a different root than the one that holds the data (a reboot, a manual foreground run with a different `--root`).                                                                                                                                                                                                                                                                                  |
| A session runs, but the console never lists it                                                        | `session_metadata_outbox` on the owning daemon by `sessionId`                                                                                          | The snapshot never reached or was never acknowledged by the Control Plane; `failedAttempts` and `nextAttemptAt` say which.                                                                                                                                                                                                                                                                                              |
| A cron run stays `running` with null `sessionId` and `durationMs`                                     | `cron_run` age against `CRON_RUN_TTL_SEC`                                                                                                              | A lost completion report; the reaper fails it after the TTL. If the daemon's `cron_runs` shows it finished, the report was lost on the wire.                                                                                                                                                                                                                                                                            |
| Startup or a review takes much longer than expected                                                   | One run's `startedAt`/`preparingAt`/`turnStartedAt`/`completedAt`, head SHA and projection generation, aligned with daemon/runtime timestamps          | Build the [phase timeline](evidence-sources.md#slow-startup-or-slow-review) and separate cold from warm runs. A long preparation interval does not by itself identify image startup, checkout, or skill work.                                                                                                                                                                                                           |
| A model is missing or a changed setting appears ignored                                               | `sessions.observedRuntime`/`observedModel`, Decision and overrides, `birthStrategy`, launch log and installed adapter/CLI versions                     | Compare the [actual execution context](evidence-sources.md#missing-models-or-ignored-configuration-changes) with the current form. A daemon version or current agent setting alone does not prove what an existing turn used.                                                                                                                                                                                           |
| Git succeeds but PR creation returns 403                                                              | Caller, target repository, sanitized command, credential plane and denied capability                                                                   | Check the [credential route](evidence-sources.md#git-works-but-pr-creation-returns-403) before changing installation permissions. A contents-capable Git token does not establish PR REST capability.                                                                                                                                                                                                                   |
| A turn disappears or repeats after a restart                                                          | Same inbox id, session key and run; `completedAt`, terminal-report presence, `lastDeliveredTs`, resume and prompt evidence                             | Follow the [restart/replay recipe](evidence-sources.md#a-turn-disappears-or-repeats-after-restart). A cursor advance or `session/load` success does not establish execution or final publication.                                                                                                                                                                                                                       |
| A daemon has no local SQLite session rows                                                             | Running root, `config.json` `store.backend`, and the selected data-plane configuration path                                                            | A self-hosted daemon can use the [PostgreSQL store](evidence-sources.md#no-local-session-rows-or-a-missing-sqlite-store). An absent local file alone does not establish lost history.                                                                                                                                                                                                                                   |

When none of the rows fits, go back to the order in `SKILL.md` step 3 and record what each source shows before theorizing. A new row belongs here only once a case has been closed with evidence.
